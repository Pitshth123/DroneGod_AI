# แผนที่ 3D

ภูมิประเทศ 3 มิติใน cockpit — สตรีมตามรัศมีรอบตำแหน่งปัจจุบันเหมือนแผนที่ 2D เดิม

## ใช้งาน — 2 ปุ่มใต้แผนที่

| ปุ่ม | ทำอะไร |
|---|---|
| **3D** | สลับแผนที่ในหน้าต่างเดิมเป็น 3 มิติ · กดซ้ำกลับเป็น 2D |
| **3D จอแยก** | เปิดเป็นหน้าต่างใหม่ ลากไปโชว์อีกจอได้ · แผนที่เดิมยังใช้งานได้ตามปกติ |

เปิดพร้อมกันทั้งสองบานได้ ทั้งคู่รับตำแหน่งโดรนชุดเดียวกัน

ทั้งสองปุ่มเป็นชิปเล็กอยู่ในแถบเดียวกับพิกัด LAT/LNG ใต้แผนที่

**ในแผนที่ 3D:** ลาก = หมุน · ล้อ = ซูม · **ดับเบิลคลิกพื้น = สั่งบินไปจุดนั้น**

การ์ด **โดรน** มุมขวาบนแสดงจำนวนโดรน พร้อมรายการสีประจำลำ ความสูง และโหมดบิน
โดยใช้คำว่า “โดรน” ทั้งหมดแทน FLEET/UAV เพื่อให้อ่านตรงกับหน้าจอภาษาไทย

- กดลูกศรบนหัวการ์ดเพื่อ **พับ/กาง** รายการ เหมาะกับหน้าต่างแคบหรือจอด้านขวา
- คลิกรายการโดรนเพื่อเลือกและเปิดรายละเอียดลำนั้นใน Cockpit ทันที
- ลำที่เลือกมีกรอบสีฟ้าและ sync กับการ์ดหลัก/คำสั่งทั้งหมด

> การปรับชื่อและรูปแบบการ์ดโดรนส่วนนี้แก้โดย **Codex เมื่อวันที่ 25 สิงหาคม 2026** — ดูรายละเอียดใน [CODEX_CHANGES.md](CODEX_CHANGES.md)
(ดับเบิล ไม่ใช่คลิกเดี่ยว เพราะคลิกเดี่ยวใช้หมุนกล้อง)

จุดหมายที่สั่งจะขึ้น **เสาแสง + วงกะพริบ + เส้นประจากโดรน** เหมือนแผนที่ 2D
เส้นหดสั้นลงเองตามระยะจริง และหายไปเมื่อถึงเป้า/กด Cancel Nav

### โหมดสั่งบิน (ปุ่มรูปโดรนมุมล่างซ้าย)

เป็น **โหมดค้าง** — กดเปิดแล้วสั่งได้เรื่อย ๆ กดซ้ำเพื่อปิด
มีอยู่ทั้งแผนที่ 2D และ 3D เป็นด่านเดียวกัน (ตัวตัดสินจริงอยู่ฝั่ง Python
สถานะซิงก์กันทุกบาน — เปิดจากจอไหนอีกจอก็เห็นตรงกัน)

### ตัวคูณความสูง (มุมล่างขวา)

คลิกเพื่อวน `x1 → x1.5 → x2 → x3 → x4` (ค่าเริ่มต้น x2)

พื้นที่ราบอย่างเมืองโคราชสูงต่างกันแค่ราว **60 m ใน 8 km** ถ้าวาด 1:1 จะดูแบน
จนอ่านภูมิประเทศไม่ออก ตัวคูณช่วยให้เห็นความต่างระดับ — **แต่เป็นภาพเกินจริง
ป้ายบอกตัวคูณจึงโชว์ตลอดเวลา ห้ามเอาไปวัดความสูงหรือระยะปลอดภัยเด็ดขาด**

## ข้อมูลมาจากไหน

ทั้งภูมิประเทศและภาพพื้นเป็น **XYZ tile** ผ่าน `tile_cache.py` ตัวเดิม — cache/offline/
prefetch ใช้กลไกเดียวกับแผนที่ 2D ทั้งหมด

| ชั้น | แหล่ง | หมายเหตุ |
|---|---|---|
| ความสูง | AWS Terrarium (`/tile/dem/{z}/{x}/{y}.png`) | ความสูง(m) = `(R*256 + G + B/256) - 32768` |
| ภาพพื้น | Esri World Imagery (`/tile/sat/...`) | อันเดียวกับแผนที่ 2D · ดึงที่ zoom ละเอียดกว่าความสูง 1 ระดับ (คมขึ้น 2 เท่า) |

**สองชั้นนี้เป็นกริดเดียวกัน (z/x/y ตรงกัน)** ภาพจึงลงบนพื้นพอดีโดยไม่ต้องแปลง
พิกัดเลย — UV ของแต่ละ tile คือ 0..1 ตรง ๆ

## ความสูงของโดรน (สำคัญ)

ใช้สูตร **`ความสูงพื้นที่จุดปล่อย + alt_rel`**

- `alt_rel` = สูงจาก **จุดปล่อย** (ไม่ใช่จากพื้นใต้ตัวโดรน) เอาไปบวกกับพื้น
  ณ ตำแหน่งปัจจุบัน**ไม่ได้** — บินข้ามเนิน 60 m ก็เพี้ยน 60 m ทันที
- ความสูงพื้นที่จุดปล่อยอ่านจาก **DEM ก้อนเดียวกับที่วาดอยู่** ฐานจึงตรงกันเป๊ะ

**ทำไมไม่ใช้ `alt_abs` เป็นหลัก:** GPS ให้ความสูงเทียบ**ทรงรี WGS84** แต่ DEM
เทียบ **geoid** ในไทยต่างกันราว −30 m เอามาวางตรง ๆ โดรนจมดินได้
(`alt_abs` ใช้เป็นทางสำรองเฉพาะตอนยังไม่รู้ความสูงพื้นที่จุดปล่อย)

มีตัวกันจมดินอีกชั้น: โดรนถูกบังคับให้อยู่ไม่ต่ำกว่าผิวภูมิประเทศเสมอ

## ความสามารถ — เท่าแผนที่ 2D

| ทำได้ | หมายเหตุ |
|---|---|
| คลิกการ์ดโดรน → เลื่อนไปหา + **วงขาวกะพริบ** | **คงมุมกล้อง/ระยะซูมที่หมุนไว้** เลื่อนแบบแพนเฉย ๆ ไม่รีเซ็ตกลับมุมตั้งต้น |
| **เส้นรอยบินที่ผ่านมา** | เส้นทึบตามรอยจริงใน 3 มิติ (เห็นทั้งเส้นทางและระดับความสูง) เก็บ 500 จุดเท่าฝั่ง 2D |
| ★ หัวขบวน (Head) | วงแหวนทองหมุนรอบลำแม่ |
| เส้นขบวน แม่→ลูก | ตอนอยู่โหมด Swarm |
| จุดหมาย + เส้นประนำทาง | **ทาบไปกับพื้น** จากใต้ตัวโดรนถึงเป้า หดสั้นลงตามระยะจริง |
| Geofence | วาดเป็น **กำแพงโปร่งสูง 400 m** เห็นขอบเขตในสามมิติ |
| เส้นทาง Waypoint | จุด + เสา + เส้นประ · จุดที่ผ่านแล้วจางลง |
| จุด GCS | เสาสัญญาณสีฟ้า |
| สีประจำลำ | ใช้สีที่ผู้ใช้เลือกใน cockpit ทุกชิ้น (ตัวโดรน/เส้น/จุดหมาย) |
| พิกัดใต้เมาส์ | ส่งเข้าแถบ LAT/LNG ใต้แผนที่เหมือนกัน |

**หมุดโดรน** เป็นโมเดลควอดคอปเตอร์ (ลำตัว + แขน 4 + มอเตอร์ + ใบพัด + ขาลง)
หัวสีขาวบอกทิศ · ใบพัดหมุนเฉพาะลำที่ **armed** · ขนาดคงที่บนจอทุกระยะซูม
(โดรนจริงกว้างไม่ถึงเมตร ถ้าวาดตามสเกลบนแผนที่กว้างหลายกิโลจะเล็กกว่า 1 พิกเซล)

ค่าเริ่มต้น z13 (≈19 m/px) รัศมี 3 tile = 7×7 รอบจุดกลาง ขยับกล้องไปทางไหน
ระบบจะเติม tile ทางนั้นแล้วปล่อย tile ที่หลุดรัศมีทิ้ง (กัน VRAM บวมเมื่อบินไกล)

## จุดกึ่งกลางฉาก

เรียงตามลำดับ: `home` ของลำแรกที่รู้จัก → ตำแหน่งโดรนล่าสุดที่มี GPS → ค่าเริ่มต้น (โคราช)
ลำที่ยังไม่มี fix (0,0) ถูกข้าม — ไม่งั้นฉากจะไปโผล่กลางอ่าวกินี

## ข้อจำกัดที่ต้องรู้

### ⚠️ ห้ามใช้ความสูงจากแผนที่นี้ตัดสินใจเรื่องการบิน

DEM ที่ z13 ละเอียดราว **19 m ต่อจุด** และเป็นข้อมูลผิวโลกทั่วไป
ใช้เป็น**ฉากให้เห็นภาพรวม**เท่านั้น — **ห้ามเอาไปคำนวณความสูงเหนือพื้น (AGL),
terrain avoidance หรือความปลอดภัยการบินใด ๆ** ความคลาดเคลื่อนสูงเกินกว่าจะเชื่อได้
ความสูงที่เชื่อได้มีทางเดียวคือค่าจาก FC เอง

### QtWebEngine 5.15.2 = Chromium 83

ตัวเรนเดอร์เก่ากว่าที่หลายไลบรารีสมัยนี้ต้องการ ถ้าจะแก้โค้ดใน `assets/map3d/`
ต้องเขียนตามข้อจำกัดนี้:

- ❌ **import maps** — ต้อง import ด้วย path ตรง
- ❌ **top-level await** — ห่อด้วย `async function`
- ❌ **dynamic `import()`** — พังทุกครั้ง (แต่ `fetch()` ไฟล์เดียวกันได้ปกติ) ใช้ static import เท่านั้น
- ✅ WebGL 2, ES modules, `ResizeObserver`

**three.js ใช้ได้ถึง r170 เท่านั้น — r178+ โมดูลไม่ยอม evaluate แล้วจอดำเงียบ ๆ**
มีเทสต์ล็อกเวอร์ชันไว้ที่ `tests/test_map3d.py::test_three_is_r170_not_newer`

### ทดสอบ

ตรรกะฝั่ง Python ทดสอบ headless ได้ตามปกติ:

```bash
cd frontend && QT_QPA_PLATFORM=offscreen SWARMGOD_NO_MAP=1 python -m unittest tests.test_map3d
```

แต่ **ตัวเรนเดอร์จริงทดสอบ headless ไม่ได้** — QtWebEngine + platform offscreen
= segfault ต้องเปิดหน้าต่างจริง:

```bash
python prototypes/map3d/check_cockpit3d.py
```

สคริปต์นี้เปิด cockpit จริง กดปุ่มทั้งสอง แล้วอ่านจำนวน tile/fps/หมุด/ขนาด canvas
กลับมาจากในหน้าเว็บ (ควรมี core + SITL รันอยู่จะได้เห็นหมุดขยับ)

> **หมายเหตุการเก็บภาพ:** `QWidget.grab()` จับ layer ที่ GPU composite ไม่ได้ →
> ได้ภาพดำล้วน ต้องดึงผ่าน `map3d.capture()` (canvas.toDataURL) แทน
> และต้องเป็น JPEG — PNG ของจอใหญ่โตหลาย MB จนส่งข้ามสะพาน JS→Python ไม่รอด

## ประสิทธิภาพที่วัดได้

Intel Iris Xe · z13 รัศมี 3 (49 tiles)

| กรณี | ผล |
|---|---|
| หน้า 3D อย่างเดียว | 60 fps · ~500-600k tris/เฟรม |
| ใน cockpit (บานเดียว) | ~33 fps |
| เปิดพร้อมกันทั้งฝังและจอแยก | ~21-33 fps ต่อบาน |

ถ้าเครื่องช้าปรับได้ผ่าน query string ของ `map3d.html` โดยไม่ต้องแก้โค้ด:

| พารามิเตอร์ | ค่าเริ่มต้น | ผล |
|---|---|---|
| `seg` | 96 | ความละเอียดตาข่ายต่อ tile — `seg=48` เร็วขึ้น ~4 เท่า แต่ภูมิประเทศเรียบลง |
| `radius` | 3 | 3 = 7×7 tiles · ลดเป็น 2 (5×5) ถ้าอยากโหลดน้อยลง |
| `zoom` | 13 | ระดับ tile (≈19 m/px) |
| `exag` | 2 | ตัวคูณความสูงเริ่มต้น |
| `imgup` | 1 | ภาพคมกว่าความสูงกี่ระดับ (0 = ประหยัดสุด, 2 = คมสุด กิน VRAM 4 เท่า) |

ตำแหน่งโดรนส่งเข้าฉากรวดเดียวทั้งฝูงที่ 10 Hz (ไม่ใช่ทีละลำทุกแพ็กเก็ต) —
`runJavaScript` ต้อง marshal ข้าม process ทุกครั้ง ยิงถี่กว่านี้เปลืองเปล่า
