# กลุ่มโดรน + โหมด WAVE — สเปกสำหรับลงมือทำ

> สถานะ: **Codex ดำเนินการแล้ว (25 สิงหาคม 2026)** · ระบบกลุ่ม, Waypoint action A/B และ WAVE ถูกเพิ่มใน Python Cockpit พร้อม regression tests
> ผู้ทำไม่จำเป็นต้องรู้ที่มาของงาน — ทุกอย่างที่ต้องรู้อยู่ในนี้

## 0. สรุปสั้นที่สุด

เพิ่ม 2 อย่างที่แยกกันชัดเจน:

**A. กลุ่ม (Groups)** — จำไว้ว่าโดรนลำไหนอยู่กลุ่มไหน กดเลขกลุ่มแล้วเลือกลำในกลุ่มนั้นทันที
เทียบเท่ากับผู้ใช้ Ctrl+คลิกเลือกเองทีละลำ **ไม่มีอะไรมากกว่านั้น**

**B. WAVE** — สวิตช์ที่อยู่ **ในโหมด Waypoint เท่านั้น**
เปิดแล้วกด EXECUTE = แต่ละกลุ่มผลัดกันบินเส้นทางเดียวกัน ทีละกลุ่ม
บวกความสามารถใหม่: **กำหนดให้ปล่อยของ (servo A/B) ที่จุด waypoint ได้**

> ⚠️ WAVE **ไม่ยุ่ง**กับปุ่ม TAKE OFF / RTL / LAND / GOTO / ARM / HOLD / E-STOP
> ปุ่มพวกนั้นทำงานเหมือนเดิมทุกประการไม่ว่าสวิตช์ WAVE จะเปิดหรือปิด

## 1. ทำความรู้จักโค้ดที่มีอยู่ก่อน

โปรเจคนี้เป็น Ground Control Station คุมฝูงโดรน ArduPilot
**Python cockpit (PyQt5)** ↔ gRPC/mTLS ↔ **Go core** ↔ MAVLink ↔ โดรน

งานนี้อยู่ที่ **Python cockpit ฝั่งเดียวเท่านั้น — ไม่แตะ Go core และไม่แตะ .proto**

### ไฟล์ที่เกี่ยวข้อง

| ไฟล์ | มีอะไร |
|---|---|
| `frontend/swarmgod_gui/app.py` | `GroundStation` — หน้าต่างหลัก ทุกอย่างอยู่ในนี้ (~5,700 บรรทัด) |
| `frontend/swarmgod_gui/widgets/fleet_item.py` | `FleetItem` — การ์ดโดรน 1 ลำในแผงซ้าย สูงคงที่ 64px |

| `frontend/swarmgod_gui/core/ip_store.py` | `IpStore` — SQLite เก็บ IP รายลำ **ใช้เป็นแบบให้ `GroupStore`** |
| `frontend/swarmgod_gui/core/theme.py` | สี/ฟอนต์/สไตล์ปุ่มทั้งหมด |

### API ที่จะได้ใช้ (มีอยู่แล้ว ห้ามเขียนใหม่)

```python
# ── การเลือกโดรน (app.py) ──
self._selected_or_all() -> list[int]   # ลำที่เลือกอยู่ — คำสั่งทุกอันใช้ตัวนี้
self._selected_id: int                 # ลำที่โฟกัส (การ์ดล่างแสดงลำนี้)
self._on_fleet_click(did, ctrl)        # คลิกการ์ด (ctrl=True คือเลือกเพิ่ม)
self._on_fleet_toggled(on)             # ปุ่ม FLEET เลือกทั้งหมด/ยกเลิก
self.fleet_items: dict[int, FleetItem] # การ์ดทั้งหมด key = drone_id
self._connected_ids() -> list[int]     # ลำที่ยัง online

# ── แจ้งผู้ใช้ ──
self._show_toast(text, "ok"|"err"|"info")
self._log(text, vehicle=..., category="COMMAND", severity="WARNING")
self._guard() -> bool                  # False = โหมด REMOTE ล็อกอยู่ ห้ามสั่ง

# ── waypoint ที่มีอยู่ ──
self._waypoint_mode: bool              # เปิดโหมดวางจุดอยู่ไหม
self._wp_separate: bool                # False=GROUPED(ไปพร้อมกัน) True=SEPARATE(แยกลำ)
self._waypoint_route: WaypointRoute    # เส้นทางร่วม (GROUPED)
self._wp_routes: dict[int, WaypointRoute]  # เส้นทางรายลำ (SEPARATE)
self._waypoint_executing: bool
self._wp_target_ids: list[int]         # ลำที่กำลังบินตามเส้นทาง
self._wp_current_index: int            # ถึงจุดที่เท่าไรแล้ว (GROUPED)
self._wp_execute()                     # ปุ่ม EXECUTE ROUTE
self._wp_advance()                     # สั่งไปจุดถัดไป (GROUPED)
self._wp_finish()                      # จบเส้นทาง
self._abort_waypoint_execution()       # ยกเลิก (E-STOP/Cancel Nav เรียกตัวนี้อยู่แล้ว)
self._on_target_reached(drone_id)      # แผนที่แจ้งว่าถึงจุดแล้ว → เดินหน้าต่อ

# ── servo ปล่อยของ (grpc_client.py) ──
self.client.servo_set(drone_id, channel, pwm)    # A=ch7, B=ch8, pwm 1000-2000
self.client.servo_release(drone_id, channel)     # คืนช่องให้รีโมท
self.client.rtl(ids)                             # กลับฐาน
self.client.land(ids)
```

### กฎเหล็กของโปรเจคนี้

1. **คำสั่งทุกอันต้องวิ่งผ่าน `_selected_or_all()`** — ห้ามสร้างทางลัดส่งคำสั่งเอง
   เพราะด่านความปลอดภัย (safety envelope + audit) อยู่ที่ Go core และผูกกับเส้นทางนี้
2. **UI คือกระจก ไม่ใช่สมอง** — ตรรกะที่เทสต์ได้ให้แยกไว้ใน `core/*.py` ไม่มี Qt ปน
3. **ห้ามให้ widget แถวเดียวบีบไม่ได้** — อ่าน §7 ก่อนเขียน UI (เคยทำหน้าต่างกว้างเกินจอมาแล้ว)

## 2. เฟส A — กลุ่ม

### 2.1 โครงข้อมูล

```python
group_of: dict[int, int]    # {drone_id: group_no}  group_no = 1..6
```

- **1 ลำอยู่ได้กลุ่มเดียว** — ถ้าซ้อนกันได้ ตอนเวฟไล่ทำจะสั่งซ้ำลำเดิม
  อยากสั่ง 2 กลุ่มพร้อมกัน → Ctrl+คลิกสองชิป
- **สูงสุด 6 กลุ่ม** — พอดีชุดสี `DRONE_COLORS` และความกว้าง sidebar (376px)
- ลำที่ไม่ได้อยู่กลุ่มไหน = ไม่มี key ใน dict

### 2.2 เก็บถาวร — `core/group_store.py` (ไฟล์ใหม่)

ทำตามแบบ `core/ip_store.py` เป๊ะ ๆ (อ่านไฟล์นั้นก่อนเขียน):

```python
class GroupStore:
    """เก็บกลุ่มของโดรนลง SQLite — ไฟล์เดียวกับ IpStore"""
    def set_group(self, drone_id: int, group_no: int) -> None   # group_no=0 = เอาออกจากกลุ่ม
    def get_all(self) -> dict[int, int]
    def clear_drone(self, drone_id: int) -> None
```

- ใช้ `_default_db_path()` แบบเดียวกับ `ip_store.py` (มี logic กัน test แตะ DB จริงอยู่แล้ว — **ต้องคัดลอกมา**)
- ตาราง `CREATE TABLE IF NOT EXISTS drone_groups (drone_id INTEGER PRIMARY KEY, group_no INTEGER NOT NULL, updated_at REAL NOT NULL)`
- ตอนโหลด: **ทิ้งลำที่ไม่มีในฝูงแล้ว** และทิ้ง `group_no` ที่ไม่อยู่ในช่วง 1-6

### 2.3 หน้าตา — แถวชิปเหนือรายชื่อโดรน

อยู่ใน `_build_left()` ระหว่างปุ่ม SCAN/CONNECT กับ `fleet_scroll`

```
FLEET                          ● 4/4 ONLINE
[TCP ▾] [192.168.40.86:5760          ]
[   SCAN   ] [   CONNECT   ]
───────────────────────────────────────────
กลุ่ม  [ทั้งหมด] [1]³ [2]² [3]  [4] [5] [6]
───────────────────────────────────────────
 D1  Drone 1   ①              ★  READY
 D2  Drone 2   ②                 READY
```

**ชิปกลุ่ม:**
- ตัวเลข + จำนวนลำห้อยท้ายเป็นตัวยก (`[1]³`) — เห็นจำนวนโดยไม่ต้องกด
- กลุ่มว่าง = สีจาง กดไม่ได้ (`setEnabled(False)`) กันสั่งคำสั่งไปที่ชุดว่าง
- สไตล์: ใช้ `theme.tinted_btn(color, radius=8, font=11)` สีตาม `drone_color(group_no)`
- ชิป "ทั้งหมด" = เรียก `_on_fleet_toggled(True)` ที่มีอยู่แล้ว
- ความสูงชิป 26px

**ป้ายกลุ่มบนการ์ดโดรน** (`fleet_item.py`):
- วงกลมเล็กมีเลขกลุ่ม สี = `drone_color(group_no)` ขนาด ~16px
- วางต่อจากชื่อโดรน
- ไม่มีกลุ่ม = ซ่อน **แต่ต้องกันพื้นที่ไว้** (ดู §7)

### 2.4 การใช้งาน

| ทำอะไร | วิธี |
|---|---|
| เลือกกลุ่ม | คลิกชิป → `_select_group(n)` |
| เลือกหลายกลุ่ม | Ctrl+คลิกชิป → เพิ่มเข้า selection เดิม |
| กำหนดลำที่เลือก → กลุ่ม | **คลิกขวา**ที่ชิป → เมนู "กำหนด N ลำที่เลือกเป็นกลุ่ม X" |
| ย้ายลำเดียว | คลิกขวาที่การ์ดโดรน → เมนูย่อย "กลุ่ม ▸ 1..6 / ไม่มีกลุ่ม" |
| คีย์ลัด | `1`–`6` เลือก · `Ctrl+1`–`6` กำหนด |

> ใช้**คลิกขวา** ไม่ใช้ "โหมดแก้ไขกลุ่ม" เพราะโหมดมีสถานะให้ค้าง
> ลืมปิดแล้วไปคลิกการ์ดตอนจะสั่งบิน จะกลายเป็นแก้กลุ่มแทน — ความเสี่ยงที่ไม่จำเป็นต้องมี

### 2.5 พฤติกรรม

```python
def _select_group(self, group_no: int, additive: bool = False) -> None:
    """เลือกลำในกลุ่มนี้ — มีผลเท่ากับผู้ใช้ Ctrl+คลิกเลือกเองทีละลำ"""
```

- เลือก**เฉพาะลำที่ยัง online** — ลำที่หลุดถูกข้าม **พร้อมแจ้ง** ไม่ใช่เงียบ
  → `self._show_toast(f"กลุ่ม {n}: ข้าม {k} ลำที่หลุดการเชื่อมต่อ", "err")`
- ทุกลำในกลุ่มหลุดหมด → ไม่เปลี่ยน selection + แจ้ง
- ต้องเรียก `self._push_map3d_view()` ต่อท้าย (แผนที่ 3D จะได้ไฮไลต์ตาม)
- **ห้ามส่งคำสั่งบินใด ๆ** — ฟังก์ชันนี้เปลี่ยนแค่ selection

**ตัวแม่ (Head) ต้องอยู่ในกลุ่ม:** ถ้าเลือกกลุ่มแล้ว `self._head_id` ไม่ได้อยู่ในกลุ่มนั้น
ให้ย้าย Head ไปเป็นลำแรกของกลุ่ม (`self._apply_head(did, push=True, reason="group")`)
ไม่งั้นตอนเข้าโหมด Swarm ลูกจะไปเกาะลำนอกกลุ่ม

## 3. เฟส B — WAVE (อยู่ใน Waypoint เท่านั้น)

### 3.1 กติกา

```
WAVE ปิด (ค่าเริ่มต้น)
    กด EXECUTE → ตรวจ TAKEOFF → กลุ่ม/ลำที่เลือกบินตามเส้นทาง → จบ

WAVE เปิด
    กด EXECUTE → ตรวจ/ถาม TAKEOFF กลุ่ม 1 → บินครบเส้นทาง → กลับฐาน → ลงจอด
               → ตรวจ/ถาม TAKEOFF กลุ่ม 2 → บินเส้นทางเดียวกัน → กลับฐาน → ลงจอด
               → ... จนครบกลุ่มที่ติ๊กไว้
```

> **แก้ไขเพิ่มเติมโดย Codex ตามคำขอผู้ใช้ 25 สิงหาคม 2026:** หากลำเป้าหมายยังไม่บิน
> EXECUTE ROUTE จะถามยืนยัน TAKEOFF พร้อมรายชื่อและความสูง เมื่อยืนยันจะรอ telemetry
> ยืนยัน Armed + `alt_rel >= 1.5 m` ก่อนส่ง GOTO (timeout 90 วินาที) และตรวจซ้ำทุกกลุ่ม
> ใน WAVE กลุ่มที่บินอยู่ครบแล้วจะไม่ถามซ้ำ

**ทำไมต้องกลับฐาน+ลงจอดก่อนกลุ่มถัดไปออก:** ทุกกลุ่มบินเส้นทาง *เดียวกัน*
ถ้ากลุ่มก่อนยังลอยอยู่บนเส้นทาง กลุ่มถัดไปจะบินไปชน
RTL ของ ArduPilot คือกลับไป **จุดปล่อยของลำนั้นเอง** กลุ่มต่างกันจอดคนละที่จึงไม่ชนกันที่ฐาน

**ลำดับกลุ่ม = เลขกลุ่ม** (1 → 2 → 3) ไม่ต้องมี UI ลากสลับลำดับ
อยากเปลี่ยนลำดับก็เปลี่ยนเลขกลุ่ม

### 3.2 การกระทำที่จุด waypoint (servo A/B)

เพิ่มฟิลด์ใน `Waypoint` (`core/waypoint_logic.py`):

```python
@dataclass
class Waypoint:
    index: int
    lat: float
    lon: float
    action: str = ""        # "" | "servo_a" | "servo_b"
```

- ค่าเริ่มต้นว่าง = บินผ่านเฉย ๆ (พฤติกรรมเดิม)
- ตั้งค่าจาก UI: คลิกขวาที่จุดบนแผนที่ หรือรายการจุดในแผงขวา → "ปล่อย A / ปล่อย B / ไม่ทำอะไร"
- จุดที่มี action ต้องแสดงต่างจากจุดธรรมดาบนแผนที่ (ป้าย `A` / `B` สีต่างกัน)

**ลำดับการทำงานที่จุดที่มี action:**
```
ถึงจุด → หยุดนิ่ง (hold) → ปล่อย servo → รอ 2 วินาที → ไปจุดถัดไป
```
ห้ามปล่อยระหว่างเคลื่อนที่ — ของจะไปตกไม่ตรงจุด

### 3.3 🔴 ยืนยันก่อนปล่อยของ — บังคับ

การปล่อยของ **ย้อนกลับไม่ได้** และของตกใส่คนข้างล่างได้
ตอนนี้ปุ่ม servo A/B **ถามยืนยันทุกครั้งที่กด** (ดู `docs/SERVO_DATALINK.md`)
พอผูกกับ waypoint มันจะทำงานเองโดยไม่ถามอีก จึงต้องย้ายการยืนยันมาไว้ตอน EXECUTE:

```
ถ้าเส้นทางมีจุดที่ตั้ง action ไว้ → ต้อง confirm() ก่อนเริ่มเสมอ
แสดงให้ครบว่าจะปล่อยอะไร ที่จุดไหน กี่ครั้ง:

    ┌─────────────────────────────────────────┐
    │ เส้นทางนี้จะปล่อยของ 2 ครั้ง            │
    │                                         │
    │    จุดที่ 2  →  A (CH7)                 │
    │    จุดที่ 5  →  B (CH8)                 │
    │                                         │
    │ ถ้าเปิด WAVE จะทำซ้ำทุกกลุ่ม (3 กลุ่ม)  │
    │ รวมปล่อยทั้งหมด 6 ครั้ง                 │
    │                                         │
    │        [ ยกเลิก ]  [ ยืนยันปล่อยของ ]   │
    └─────────────────────────────────────────┘
```

ใช้ `confirm(self, title, text, ok_text="ยืนยันปล่อยของ", danger=True)`

### 3.4 หน้าตา

สวิตช์ WAVE อยู่ใน **หมวด WAYPOINT ROUTE** (`_sec_waypoint()` ใน `app.py`)
วางใต้สวิตช์ GROUPED/SEPARATE ที่มีอยู่:

```
▾ WAYPOINT ROUTE
   Waypoint Mode        [ ปิด | เปิด ]
   รูปแบบเส้นทาง        [ GROUPED | SEPARATE ]
   ────────────────────────────────────────────
   WAVE                 [ ปิด | เปิด ]          ← ใหม่
   กลุ่มที่ร่วมเวฟ       ☑1  ☑2  ☑3             ← โผล่เฉพาะตอน WAVE เปิด
   ลำดับ: 1 → 2 → 3
   ────────────────────────────────────────────
   จุดที่วางไว้: 5 จุด (ปล่อยของ 2 จุด)
   [ ▶ EXECUTE ROUTE ]
```

**WAVE เปิดต้องขึ้น banner เหลืองค้างไว้ตลอด** แบบเดียวกับโหมด REMOTE
(`self._show_banner(...)` — ดูวิธีที่โหมด REMOTE ใช้) เพราะมันเปลี่ยนความหมายของปุ่ม EXECUTE

**ตอนเวฟกำลังเดิน** แสดงความคืบหน้าในหมวดเดียวกัน:
```
   WAVE: กลุ่ม 2 จาก 3
   ✓ กลุ่ม 1  บินครบ · ลงจอดแล้ว
   ▶ กลุ่ม 2  กำลังบิน จุดที่ 3/5
   ○ กลุ่ม 3  รอคิว
   [ ■ ยกเลิกเวฟ ]
```

### 3.5 การยกเลิก — ต้องมีตั้งแต่วันแรก

เวฟคือ **งานอัตโนมัติที่เดินข้ามเวลาโดยคนไม่ได้กดทุกครั้ง** จึงต้องยกเลิกได้ทุกทาง:

- `_abort_waypoint_execution()` **ต้องยกเลิกเวฟด้วย** (E-STOP และ Cancel Nav เรียกตัวนี้อยู่แล้ว)
- ปิดสวิตช์ WAVE ระหว่างเวฟกำลังเดิน = ยกเลิก
- ปุ่ม "ยกเลิกเวฟ" ในแผง
- **ยกเลิกแล้วต้องไม่มีคำสั่งของกลุ่มถัดไปตามมาอีก** — ต้องมีเทสต์ยืนยันข้อนี้
  (ระวัง `QTimer.singleShot` ที่ตั้งไว้แล้ว — ต้องเช็คธงก่อนทำงานทุกครั้ง
   ดูวิธีที่ `_wp_advance()` เช็ค `self._waypoint_executing` เป็นแบบอย่าง)

### 3.6 เงื่อนไข/ขอบเขต

- **กลุ่มถัดไปออกเมื่อกลุ่มก่อนหน้า disarmed ทุกลำ** (ลงจอดจริง)
- ก่อนเริ่ม Route ของแต่ละกลุ่ม ต้องตรวจว่าทุกลำพ้นพื้นแล้ว ถ้ายังไม่บินให้ถามยืนยัน
  TAKEOFF เฉพาะลำที่จำเป็น และห้ามส่ง GOTO จน telemetry ยืนยัน Armed + ความสูงอย่างน้อย 1.5 m
- ปฏิเสธกล่อง TAKEOFF หรือรอเกิน 90 วินาที = หยุด/ไม่เริ่ม Route และบันทึกใน Pre-flight Summary
- **Timeout ต่อกลุ่ม** (เสนอ 5 นาที) — เกินแล้ว **หยุดเวฟทั้งชุด + แจ้ง**
  ห้ามดันกลุ่มถัดไปออกไปทับ
- WAVE ใช้ได้เฉพาะโหมด **GROUPED** เท่านั้น — SEPARATE คือแต่ละลำมีเส้นทางของตัวเอง
  ความคิดเรื่อง "ผลัดกันบินเส้นทางเดียวกัน" ใช้ไม่ได้ → เปิด WAVE ตอน SEPARATE ให้ปฏิเสธ + แจ้ง
- ต้องมีอย่างน้อย 2 กลุ่มที่มีลำอยู่จริง ถึงจะเปิด WAVE ได้

## 7. ⚠️ กับดัก UI ที่เคยพังมาแล้ว — อ่านก่อนเขียน

เคยเจอบั๊ก "แถบคำสั่งตกขอบจอ" มาแล้ว 3 ครั้ง จากสาเหตุเดียวกัน:

> **แถวของ widget ที่บีบเล็กลงไม่ได้ จะกลายเป็นความกว้างขั้นต่ำของทั้งหน้าต่าง**
> และ Qt จะไม่บังคับใช้ทันที — มันโผล่ตอนมีอะไรมาทำให้คำนวณ layout ใหม่
> (เช่นเปิดหน้าต่างใหม่ หรือข้อความในป้ายเปลี่ยนความยาว) แล้วหน้าต่างเด้งกว้างเกินจอทันที

**กฎที่ต้องทำตามในงานนี้:**

1. **ป้ายที่ข้อความเปลี่ยนความยาวได้ ต้อง `setFixedWidth()` + ตัดด้วย `…`**
   ห้ามใช้ `setVisible(False)` คุมพื้นที่ (Qt ไม่กันที่ให้ widget ที่ซ่อนอยู่)
   ```python
   lbl.setFixedWidth(150)
   fm = lbl.fontMetrics()
   lbl.setText(fm.elidedText(text, Qt.ElideRight, lbl.width()))
   lbl.setToolTip(text)     # ข้อความเต็มอยู่ใน tooltip
   ```
   ดูตัวอย่างจริงที่ `self.banner` และ `self.lbl_map3d` ใน `app.py`

2. **แถวชิปกลุ่ม 6 อัน + ป้าย "กลุ่ม" ต้องไม่บังคับความกว้าง**
   ถ้ารวมกันเกิน ~340px ให้ห่อด้วย `QScrollArea` แนวนอน
   (ดูตัวอย่างที่แถบเครื่องมือใน `widgets/mission_log.py`)

3. **ป้ายกลุ่มบนการ์ดโดรน** — การ์ดสูงคงที่ 64px และกว้างคงที่
   ป้ายต้องกันพื้นที่ไว้ตลอด ไม่ใช่โผล่/หายแล้วดันของอื่น

**ตรวจก่อนส่ง:**
```python
win.centralWidget().layout().minimumSize().width()   # ต้องไม่เพิ่มขึ้นจากก่อนแก้
```
