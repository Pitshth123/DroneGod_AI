# รายงานทดสอบคำสั่งและการป้องกันโดรนชนกัน

อัปเดตล่าสุด: 26 สิงหาคม 2026

เอกสารนี้เป็นหลักฐานว่าเทสอะไรไปแล้ว จำนวนกี่ลำ และผลเป็นอย่างไร แยกคำว่า
`PASS`, `FAIL`, `BLOCKED` และ `PENDING` ชัดเจน เพื่อไม่ให้ผลจำลองถูกตีความว่า
รับรองความปลอดภัยในการบินจริง 100%

## เกณฑ์ตัดสิน

- คำสั่งผ่านเมื่อ Core ตอบ `ok=true` และกรณีที่ต้องมีผลจริงต้องเห็น telemetry/โหมดตอบกลับ
- คำสั่งที่ Core หรือ FC ตอบ `ok=false` ต้องไม่ถูกแสดงเป็นสำเร็จ
- ถือว่าเสี่ยงชนเมื่อระยะแนวราบน้อยกว่า 5 เมตร และส่วนต่างความสูงไม่เกิน 2 เมตร
- RETURN ใช้ชั้นความสูงห่างอย่างน้อย 5 เมตรก่อนเคลื่อนแนวราบ
- จุดลงของหลายลำต้องห่างกันอย่างน้อย 5 เมตร และ LAND ทีละลำ
- การทดสอบ SITL เป็นการจำลองฟิสิกส์/FC ไม่ใช่การรับรองลม, GPS multipath,
  ความคลาดเคลื่อนเซนเซอร์ หรือความเสียหายทางกลในสนามจริง

## สรุปผลล่าสุด

- **PASS — Backend:** `go test ./...`
- **PASS — Static checks:** `go vet ./...`
- **PASS — Frontend/UI/Web:** 839 tests, 585.660 วินาที
- **PASS — RETURN target planner:** 1–20 ลำ โดยตั้งพิกัดลงซ้อนกันและพิกัดหาย
  ระบบต้องกระจายเป้าหมายทุกคู่ไม่น้อยกว่า 5 เมตร
- **PASS — Payload rejection:** HOLD ถูกปฏิเสธแล้วห้ามส่ง SERVO; SERVO ถูกปฏิเสธแล้ว
  ห้ามขึ้นเครื่องหมายว่าปล่อยสำเร็จ

  ไม่ใช่ test failure ของโปรแกรม แต่ยังนับว่าไม่ได้หลักฐานจาก race detector
- **PASS หลังแก้ — SITL 3 ลำครบวง:** FORM UP แบบย้ายทีละลำผ่านชั้นความสูง,
  เคลื่อนขบวน, RETURN และ LAND ผ่าน 530 ตัวอย่าง; ระยะสามมิติต่ำสุด 6.51 เมตร

## เมทริกซ์ที่ทดสอบอัตโนมัติแล้ว

### คำสั่งพื้นฐาน — 1 ลำและหลายลำ

- Connect/disconnect, online/offline และ telemetry สด/ค้าง
- ARM/DISARM รวม force/confirmation gate
- TAKEOFF ยืนยัน/ไม่ยืนยัน, GPS ไม่พร้อม, แบตต่ำ, preflight ไม่ผ่าน
- HOLD, GUIDED, LAND, RTL, STOP ALL และ E-STOP
- GOTO ที่ถูกต้อง, พิกัดผิด, ความสูงเกิน, geofence/radius และ telemetry หาย
- Servo A/CH7, Servo B/CH8, release/reset, exception และผลตอบกลับ `ok=false`
- คำสั่งซ้ำ, ยกเลิกกลางทาง, timeout และคำสั่งมาถึงผิด generation

### รูปขบวนและ Waypoint

- 1 ลำ, หลายลำ, GROUPED, SEPARATE และ SWARM ACTIVE
- LINE และรูปขบวนที่ระบบรองรับ พร้อมตรวจ spacing ต่ำกว่าค่าปลอดภัย
- เส้นทางตัดกัน, จุดปลายใกล้กัน, ความสูงชั้นเดียวกัน/ต่างชั้น
- Waypoint ถึงเป้าหมาย, ไม่ถึงเป้าหมาย, ยกเลิก และ auto-takeoff
- WAVE หลายกลุ่ม: กลุ่มถัดไปรอ landing/disarm, timeout แล้วหยุดทั้ง wave,
  auto-next ไม่ถามซ้ำเมื่อผู้ใช้เลือกไว้
- Payload A/B ใน WAVE: สถานะกำลังปล่อย, สำเร็จพร้อมติ๊ก, ล้มเหลวไม่มีติ๊ก

### RETURN/LAND และการลอง “จอดทับกัน”

- ทดสอบ 1 ถึง 20 ลำ โดยป้อน launch point แบบเดียวกันทั้งหมด/บางส่วน และไม่ส่งบางจุด
- Planner ต้องเก็บจุดเดิมเมื่อห่างพอ และกระจายจุดที่ซ้อนออกซ้าย/ขวาทีละ 5 เมตร
- ทุกคู่ของเป้าหมายสุดท้ายต้องห่างอย่างน้อย 4.95 เมตร (เผื่อค่าคำนวณ 0.05 เมตร)
- ต้องถึงชั้นความสูงประจำลำก่อนเริ่มบินแนวราบกลับ
- ถึงพิกัดอย่างเดียวแต่ผิดชั้นความสูง ห้ามเริ่ม LAND
- ต่ำใกล้พื้นแต่ยัง armed หรือ disarmed แต่ telemetry ยังสูง ห้ามนับว่าลงแล้ว
- หากจัดชั้น/กลับจุดลงไม่ครบ ใช้ FC RTL ทีละลำ และรอ ground+disarmed ก่อนลำถัดไป

ผลของเคส “สั่งทุกลำลงพิกัดเดียวกัน” ในเส้นทาง RETURN ของ Core คือ **ไม่ยอมให้
เป้าหมายสุดท้ายทับกัน** ระบบกระจายจุดลงก่อน และสั่งลงทีละลำ

## การทดสอบ SITL 3 ลำ

ชุดทดสอบจริงตั้งใจทำลำดับต่อไปนี้:

1. เชื่อม ArduCopter SITL 3 ลำที่พอร์ต 5760, 5770 และ 5780
2. รอ telemetry verified, GPS 3D และดาวเทียมอย่างน้อย 6
3. TAKEOFF 20 เมตร
4. จัด LINE spacing 12 เมตร
5. สั่งหัวขบวนเคลื่อนและเก็บระยะทุกคู่ทุก 0.5 วินาที
6. RETURN โดย base altitude 20 เมตร, layer gap 5 เมตร
7. รอ LAND และ disarm ครบทุกลำ พร้อมบันทึกระยะต่ำสุด

ผลรอบวินิจฉัยที่เริ่ม SITL ใหม่ทั้งหมด:

- TAKEOFF 3/3 ลำที่ 20 เมตร: PASS
- LINE formation ตั้ง spacing 12 เมตร: คำสั่ง ACCEPTED แต่การเปลี่ยนรูปขบวน FAIL ด้าน separation
- D1/D2 เข้าใกล้ 2.08 เมตรและ 2.36 เมตร ที่ส่วนต่างความสูง 0.03/0.01 เมตร
- ต้นเหตุ: D2 เริ่มอยู่ตะวันออกของ D1 แต่ slot แรกของ LINE อยู่ตะวันตก จึงบินตัดผ่าน D1
- เคลื่อนหัวขบวน: คำสั่ง ACCEPTED
- RETURN แยกชั้น + จุดลงรายลำ + LAND ทีละลำ: ครบทั้ง 3 ลำ

ผลรอบก่อนเพิ่ม phase logging พบค่าต่ำสุด 0.97 เมตร จึงถือเป็นบั๊กความปลอดภัยจริง
หลังผู้ใช้เลือกวิธีแก้แบบจัดคิวทีละลำ ระบบเปลี่ยน FORM UP เป็น:

1. ตรวจว่าพิกัดเริ่มต้นทุกคู่ห่างอย่างน้อย 5 เมตร
2. ตรึงตัวแม่
3. ยกลูกทีละลำขึ้นชั้นผ่านทางคนละชั้น โดยเพิ่ม safety margin อีก 2 เมตร
4. ย้ายแนวราบทีละลำ
5. ลดลง slot ทีละลำ
6. หากเพดานไม่พอ พิกัดหาย หรือ telemetry ไม่ยืนยันภายในเวลา ให้หยุดแบบ fail-closed

ผลยืนยันหลังแก้ด้วยสถานการณ์เดิม:

- 3 ลำ, LINE spacing 12 เมตร, TAKEOFF 20 เมตร
- FORM UP settled และคงรูปขบวน 10 วินาที: PASS
- เคลื่อนหัวขบวน 25 วินาที: PASS
- RETURN แยกชั้นและ LAND ทีละลำ: PASS ครบ 3/3
- เก็บ telemetry pair samples: 530 ตัวอย่าง
- ระยะแนวราบต่ำสุด: 2.48 เมตร ขณะลำอยู่คนละชั้น
- ระยะสามมิติจริงต่ำสุด: **6.51 เมตร** (เกณฑ์อย่างน้อย 5 เมตร)
- separation violations: 0
- ชุด UI WAVE 5 ลำ: 21 tests ผ่านทั้งหมด; ระหว่างรันพร้อมชุดอื่นพบ timing flake
  1 ครั้งในเคสรอกลุ่ม 2 และเมื่อนำเคสเดี่ยวกับทั้งไฟล์มารันซ้ำผ่าน จึงบันทึกไว้แต่
  ไม่พบ state failure ซ้ำ

## สิ่งที่ยังต้องทดสอบก่อนบินจริง

- SITL 3 ลำครบวงผ่านแล้ว; ควรรันทวนเมื่อแก้ flight controller/formation logic
- SITL แบบเริ่มใกล้กว่า 5 เมตร เพื่อยืนยันว่าด่าน preflight บล็อกก่อน TAKEOFF
- SITL เส้นทางตัดกันที่ระดับเดียวกันและต่างระดับ
- SITL ตัด telemetry/หยุดหนึ่ง FC ระหว่าง WAVE และระหว่าง RETURN
- Bench/HIL แบบถอดใบพัด: ARM→DISARM, GUIDED feedback, servo A/B และ failsafe
- บินจริงทีละ 1 ลำ ก่อนเพิ่มเป็น 2 และ 3 ลำ โดยมี pilot/RC takeover และพื้นที่ลงแยก

## วิธีรันทดสอบซ้ำ

จากโฟลเดอร์โปรเจกต์:

```powershell
cd backend
go test ./...
go vet ./...

cd ..\frontend
$env:QT_QPA_PLATFORM = "offscreen"
$env:SWARMGOD_NO_MAP = "1"
python -m unittest discover -s tests -v
```

SITL ใช้ `backend/cmd/sitlverify` และจะปฏิเสธการทำงานเมื่อ profile เป็น production
เพื่อป้องกันการเผลอส่งชุดคำสั่งทดสอบไปยังโดรนจริง
