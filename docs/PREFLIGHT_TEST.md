# PRE-FLIGHT TEST — ด่านทดสอบก่อนบินจริง

> หมวด **PRE-FLIGHT TEST** อยู่บนสุดของแผงคำสั่งฝั่งขวา (ปุ่ม `SYSTEM TEST` + `CHECKLIST`)  
> ป้าย **● PREFLIGHT** อยู่หัวแผง FLEET ข้าง `● ONLINE` (แดง=ยังไม่เทส เขียว=ผ่าน)

เอกสารนี้อธิบาย 2 ปุ่มที่ต้องผ่านก่อนปล่อยบินจริง และด่านที่ถามก่อน TAKEOFF
(ตัวเช็คลิสต์ที่ Codex เขียนไว้ยังอยู่ที่ [REAL_FLIGHT_CHECKLIST.md](REAL_FLIGHT_CHECKLIST.md)
— ปุ่มที่ 2 คือเอาไฟล์นั้นมาทำเป็น checkbox ให้ติ๊กในโปรแกรมได้)

---

## 1. ปุ่ม `SYSTEM TEST`

เครื่องตรวจให้เอง เป็นรายการสั้น ๆ เอาเฉพาะข้อที่มีผลต่อ **ความปลอดภัย** และ
**ความถูกต้องของการสั่งการ/โหมด** — ไม่ใช่รายการยาวจนไม่มีใครรอ

| กลุ่ม | ตรวจอะไร | ไม่ผ่านแล้ว |
|---|---|---|
| **LINK** | core + mTLS + `SWARMGOD_TOKEN` + `SWARMGOD_PROFILE`/`HOME_LOC` (บังคับเมื่อ production/hil) | บล็อก |
| | telemetry ของทุกลำสดภายใน 3 วิ | บล็อก |
| | สวิตช์ CONTROL อยู่ที่ UI (ไม่ใช่ REMOTE ที่ล็อกคำสั่งไว้) | บล็อก |
| | คุณภาพ datalink ≥ 40% | เตือน |
| **READY** | GPS 3D fix + ดาวเทียม ≥ 6 ทุกลำ | บล็อก |
| | แบตเตอรี่ ≥ 40% (ต่ำกว่า 55% = เตือน) | บล็อก |
| | ทุกลำ disarm และอยู่บนพื้น | บล็อก |
| | มีพิกัดจริง (ไม่ใช่ 0,0) | บล็อก |
| | จุด home ถูกบันทึกแล้ว | เตือน |
| **SEPARATION** | ระยะห่างบนพื้นทุกคู่ ≥ ค่ากันชน (ค่าเดียวกับ Collision Detection) | บล็อก |
| **CONFIG** | ความสูง TAKEOFF สมเหตุผล (> 60 m = เตือน) | บล็อก/เตือน |
| | ค่า RTL (base ≥ 10 m, gap ≥ 3 m) · Geofence ถูกบังคับใช้ | เตือน |
| | หัวขบวน (Head) ถูกตั้งและออนไลน์ — เฉพาะเมื่อบินหลายลำ | บล็อก |
| | เส้นทาง Waypoint (SEPARATE) ไม่มีคู่เสี่ยงชน | บล็อก |
| **COMMAND** | สั่ง **HOLD** แล้ว core ตอบรับ | เตือน |
| | สั่งโหมด **GUIDED** แล้ว **FC รายงานกลับมาว่าเข้าโหมดจริง** ภายใน 8 วิ | บล็อก |

ข้อสุดท้ายคือหัวใจของปุ่มนี้ — มันพิสูจน์เส้นทางเต็มวง
`cockpit → core → MAVLink → FC → telemetry กลับมา` ว่าสั่งแล้วมีผลจริง
ไม่ใช่แค่ "ยิงคำสั่งออกไปแล้วเงียบ" และจบด้วยโหมด GUIDED ซึ่งเป็นโหมดที่ TAKEOFF ต้องใช้พอดี

### ติ๊ก «ถอดใบพัดแล้ว» (bench) — ปลดล็อกอีก 2 ข้อ

ข้อพวกนี้สั่งของจริง จึงไม่รันให้อัตโนมัติ ต้องติ๊กเอง + ยืนยันอีกชั้น:

| ข้อ | ทำอะไร |
|---|---|
| TAKEOFF ที่ไม่ยืนยันถูกปฏิเสธ | ยิง `Takeoff(confirmed=false)` — core **ต้องปฏิเสธ** ถ้ายอมรับ = ถือว่าไม่ผ่านทันที และระบบสั่ง DISARM กลับให้เอง |
| ARM → DISARM | พิสูจน์ว่าผ่าน pre-arm ของ FC จริงและดับมอเตอร์กลับได้ |

> ⚠ ห้ามติ๊กถ้าใบพัดยังอยู่ — มอเตอร์จะหมุนจริง

### ลำดับที่ยึดไว้

ถ้ามีข้อ **บล็อก** ไม่ผ่านตั้งแต่รอบตรวจแรก ระบบจะ **ไม่ยิงคำสั่งใด ๆ ใส่โดรนเลย**
(กลุ่ม COMMAND ขึ้นเป็น "ข้าม") — ไม่ไปแหย่โดรนที่สถานะยังไม่ปลอดภัย

## 2. ปุ่ม `CHECKLIST` (เช็คลิสต์ของ Codex)

อ่าน `docs/REAL_FLIGHT_CHECKLIST.md` มาแสดงเป็น checkbox แยกตามหมวด A–D
(หมวด E เป็นช่องเซ็นรับรอง ไม่มี checkbox จึงไม่ถูกนับ)

- ติ๊กเองตามที่ตรวจจริงในสนาม — ข้อพวกนี้เครื่องตรวจแทนไม่ได้
  (ถอดใบพัดหรือยัง · cert ชุดนี้แจกใครไปบ้าง · มีพื้นที่จุดลงแยกไหม)
- สถานะที่ติ๊กถูกเก็บที่ `~/.swarmgod/preflight_checklist.json` จึงข้ามรอบเปิดโปรแกรมได้
- คีย์ของแต่ละข้อคิดจากตัวข้อความ — แก้ลำดับในเอกสารแล้วเครื่องหมายไม่เลื่อน
  แต่ถ้าแก้ **ข้อความ** ของข้อไหน ข้อนั้นจะกลับมาเป็นยังไม่ติ๊ก (ตั้งใจ — ข้อเปลี่ยนแล้วต้องตรวจใหม่)
- ผ่าน = ติ๊กครบทุกข้อ

## 3. ถ้ายังไม่ได้เทสแล้วสั่ง TAKEOFF

ทุกทางที่ทำให้โดรนลอยขึ้นจริงผ่านด่านเดียวกัน:
ปุ่ม TAKEOFF ในหมวด FLIGHT · TAKE OFF ในแผง (All/Sequential) · SWARM TAKE OFF ·
AUTO TAKEOFF ก่อน EXECUTE ROUTE ของ Waypoint/WAVE

ระบบจะถามก่อน พร้อมบอกว่าขาดอะไร:

| ตอบ | เกิดอะไรขึ้น |
|---|---|
| **RUN TEST** | เปิดชุดทดสอบให้ทันที (และเช็คลิสต์ถ้ายังไม่ได้กรอก) — ผ่านแล้ว **สั่ง TAKEOFF ต่อให้เลย** ไม่ต้องกดซ้ำ · ถ้ายังไม่ผ่านจะถามอีกครั้งว่าจะบินต่อไหม |
| **SKIP · TAKEOFF** | สั่งขึ้นบินตามที่กด แต่ขึ้น banner แดง + เขียน log ระดับ ERROR ว่าข้ามด่านครั้งที่เท่าไร |
| **CANCEL** | ไม่มีคำสั่งใดถูกส่งออกไป |

ปุ่ม **ARM** เตือนอย่างเดียวไม่บล็อก (ARM ยังไม่ใช่การขึ้นบิน — ด่านจริงอยู่ที่ TAKEOFF)

### ป้ายเตือน

| ป้ายข้าง ONLINE | ความหมาย |
|---|---|
| 🔴 `⚠ PREFLIGHT` แดง | ยังไม่ได้รันสักปุ่ม — มีแถบเตือนค้างใต้ topbar |
| 🟠 `● PREFLIGHT` เหลือง | ผ่านอย่างเดียว หรือมีอันหนึ่งไม่ผ่าน |
| 🟢 `● PREFLIGHT` เขียว | ผ่านครบ — TAKEOFF จะไม่ถูกถามซ้ำ |

ทรงเดียวกับป้าย `● CORE` / `LINK` — บอกสถานะด้วยสี รายละเอียดอยู่ใน tooltip

กดที่ป้ายเพื่อกางหมวด PRE-FLIGHT TEST ให้เลย

### ผลเทสอยู่ได้นานแค่ไหน

- ผลอยู่ **ตลอดการเปิดโปรแกรมครั้งนั้น** ไม่หมดอายุตามเวลา
- เก็บใน **หน่วยความจำเท่านั้น** — ปิดแล้วเปิดใหม่ = ต้องเทสใหม่ (fail-closed)
- เครื่องหมายในเช็คลิสต์ยังอยู่ข้ามรอบ แต่ตัว "ผ่านแล้ว" ต้องเปิดกดยืนยันใหม่
- ถ้าอยากบังคับให้หมดอายุตามเวลาด้วย ตั้ง `PreflightState(ttl_s=<วินาที>)` ได้

## 4. โครงสร้างโค้ด

| ไฟล์ | หน้าที่ |
|---|---|
| `frontend/swarmgod_gui/core/preflight.py` | ตรรกะล้วน ไม่มี Qt — เกณฑ์ทุกข้อ, สรุปผล, parse เช็คลิสต์, `PreflightState` |
| `frontend/swarmgod_gui/widgets/preflight_dialog.py` | popup ทั้ง 2 ใบ + กล่องถามก่อน TAKEOFF |
| `frontend/swarmgod_gui/app.py` | `_sec_preflight` (หมวด) · `_preflight_snapshot` (ป้อนข้อมูล) · `_preflight_gate` (ด่าน) |
| `frontend/tests/test_preflight.py` | 39 เทส — เกณฑ์ทุกข้อ, popup กับ fake client, ด่านก่อน TAKEOFF |

แยก `core/preflight.py` ออกจาก Qt เพื่อให้เกณฑ์ความปลอดภัยทั้งหมดเทสได้แบบ headless
และให้ popup เป็นแค่ตัวแสดงผล ไม่ใช่ที่เก็บกฎ

```bash
cd frontend && QT_QPA_PLATFORM=offscreen SWARMGOD_NO_MAP=1 python -m unittest tests.test_preflight -v
```

## 5. สิ่งที่ปุ่มนี้ **ไม่ได้** รับรอง

- ไม่ได้ตรวจ airframe/ใบพัด/สายไฟ/จุดศูนย์ถ่วง
- ไม่ได้ตรวจ failsafe ฝั่ง FC (radio/GCS/battery) — ต้องตั้งและทดสอบที่ FC เอง (หมวด A/B ของเช็คลิสต์)
- ไม่ได้แทนการบินทดสอบทีละลำแบบ tethered (หมวด C ของเช็คลิสต์)

ผ่านทั้ง 2 ปุ่ม = "ระบบภาคพื้นและเส้นทางสั่งการพร้อม" เท่านั้น ไม่ใช่ "ปลอดภัยแน่นอน"
