## 0.1 ⚠ ข้อขัดกับสเปกเดิม — ต้องอ่านก่อนแตะ MOVEMENT

`FIELD_TABLET.md §3.1 ข้อ 3` เขียนไว้ว่า **ห้ามเปิด RcMove/SetYaw ผ่านเว็บเด็ดขาด**
เหตุผลเดิม: WiFi กระตุก 300 ms ตอนบังคับสด = โดรนวิ่งต่อโดยไม่มีคนสั่ง

ผู้ใช้สั่งให้ทำ MOVEMENT บนแท็บเล็ต → **ทำตาม** แต่ต้องมีตัวกันครบชุดข้างล่างนี้
และถือว่าข้อนี้เป็น **ข้อยกเว้นที่ตั้งใจ** ไม่ใช่ลืมกฎ:

| ตัวกัน | รายละเอียด | สถานะ |
|---|---|---|
| deadman ฝั่ง Python | เว็บสั่ง move ได้ครั้งละ ≤ `WEB_MOVE_TTL` (1.2 วิ) ไม่มีคำสั่งต่อ = หยุดเอง | [x] |
| ต้องกดปลดล็อกก่อน | ปุ่ม "ปลดล็อกบังคับสด" บนแท็บเล็ต ปิดเองเมื่อสลับแท็บ/ออกจากหน้า | [x] |
| PILOT เท่านั้น | viewer สั่ง move ไม่ได้เลย (server ปฏิเสธ ไม่ใช่แค่ซ่อนปุ่ม) | [x] |
| bucket แยก | move ยิงถี่ได้ (10/วิ) แต่ยังมีเพดาน ไม่ปนโควตาคำสั่งปกติ | [x] |
| หยุดทันทีเมื่อออกจากหน้า | `pagehide`/`visibilitychange`/ปล่อยนิ้ว → ส่ง `move_stop` | [x] |
| ความเร็วจำกัด | เว็บสั่งได้ ≤ 3 m/s เสมอ (คอกพิตปรับได้ถึง 15) | [x] |

> ถ้าเจ้าของโปรเจกต์ไม่โอเคกับข้อยกเว้นนี้ ให้ลบ `move`/`move_stop` ออกจาก
> `MOVE_COMMANDS` ใน `field_server.py` แล้วซ่อนแท็บ MOVE ใน `tablet.html` — จบ
> ส่วนที่เหลือทั้งหมดไม่ผูกกับ MOVEMENT

## 1. ทำไมของเดิมช้า (วิเคราะห์จากโค้ดจริง ไม่ใช่เดา)

`assets/tablet.html` เดิม:

1. **`innerHTML` ทั้งก้อนทุกเฟรม** — `render()` ประกอบสตริงรายชื่อโดรนใหม่ทั้งหมด
   แล้วยัดกลับ `#dlist` ที่ 5 Hz → ทุกแถวถูกลบ/สร้างใหม่วินาทีละ 5 รอบ
   นิ้วที่แตะค้างอยู่บนแถวจึงโดนลบทิ้งกลางทาง = **"กดแล้วไม่ไป"** ตัวจริง
2. **`m.setIcon(icon(...))` ทุกเฟรม** — สร้าง `divIcon` ใหม่ = Leaflet ถอด DOM
   ของหมุดทิ้งแล้วสร้างใหม่ทุกครั้ง (5 ลำ × 5 Hz = 25 หมุดใหม่/วิ)
3. **`renderInfo()` เขียน `innerHTML` ซ้ำทุกเฟรม** ทั้งที่ค่าเปลี่ยนไม่กี่ตัว
4. **ไม่มี `touch-action`** บนปุ่ม → บราวเซอร์รอ ~300 ms เผื่อ double-tap zoom
5. **`applyControl()` ถูกเรียกทุกเฟรม** → เขียน `className`/`textContent`
   ของปุ่มทุกใบใหม่ทั้งชุด + `querySelectorAll` ซ้ำ ๆ
6. SSE ยิงทุกครั้งที่ `seq` ขยับ ซึ่งขยับทุกแพ็กเก็ต telemetry → payload เต็มก้อน 5 Hz

### วิธีแก้ (ทำในเวอร์ชันใหม่)
- แถวโดรน **สร้างครั้งเดียวแล้ว reuse** (`rowCache[id] = {el, refs}`) อัปเดตเฉพาะ
  `textContent` ที่เปลี่ยนจริง — ไม่มี `innerHTML` ใน hot path เลย
- หมุด: สร้าง `divIcon` ครั้งเดียวต่อลำ แล้วขยับด้วย `setLatLng` +
  หมุนหัวด้วย `style.transform` บน element เดิม ไม่เรียก `setIcon` อีก
- `applyControl()` เรียกเฉพาะตอน `control.gen` เปลี่ยน (server ส่ง `gen` มาให้)
- ทุกปุ่มมี `touch-action:manipulation`
- วาดจาก SSE ผ่าน `requestAnimationFrame` (ทบเฟรม ไม่วาดซ้อน)
- หยุดวาดเมื่อ `document.hidden`

## 2. ผังหน้าจอใหม่

```
┌──────────────────────────────────────────────────────────┐
│ [☰]                                    [👁ผู้ชม][●LAN]   │ แถบบน (ลอย)
│                                        ┌────────────────┐│
│                                        │ ⌃ โดรน     (5) ││ ← ขวา: แถบโดรน
│   แผนที่เต็มจอ (Leaflet + tile cache)   │ ◆ Drone 1  0 m ││   ทรงเดียวกับ
│   แตะแผนที่ในโหมด WP = วางจุด           │   กลุ่ม1·GUIDED ││   map3d #fleet
│                                        │ ◆ Drone 2  0 m ││
│                                        └────────────────┘│
│ ┌──────────┐                           ┌────────────────┐│
│ │ การ์ดลำ  │                           │  แผงคำสั่ง     ││ ← เปิด/ปิดด้วย ☰
│ │ ที่เลือก │                           │  (4 แท็บ)      ││
│ └──────────┘                           └────────────────┘│
│ [E-STOP]                    [FLIGHT][WP][SWARM][MOVE]    │ ← แถบแท็บ
└──────────────────────────────────────────────────────────┘
```

- **แถบโดรนขวาบน** = ของใหม่ตามข้อ 2 ของผู้ใช้ ลอกสไตล์ `#fleet` ใน `map3d.html`
  (การ์ด `rgba(10,16,20,.92)`, grid `10px 1fr auto`, จุดเพชรหมุน 45°,
  `กลุ่ม N · MODE`, ตัวเลข `0 m` ขวาสุด, ปุ่ม `⌃` พับได้, ตัวนับสีเขียว)
  ต่างจากของ 3D แค่: แตะแล้ว = เลือกลำ (ส่ง `select`) + แสดง % แบต + สถานะค้าง
- **แผงคำสั่ง** เปลี่ยนจาก "กองปุ่มยาว ๆ" เป็น **4 แท็บ**: FLIGHT / WAYPOINT /
  SWARM / MOVE — แท็บเล็ตกลางแดดเลื่อนหาปุ่มยาก
- **ไม่มี**: เครื่องมือวาด geofence/tactical, CV track (ตามที่สั่ง)

## 13. ประเมินความพร้อมบินจริง (25 ส.ค. 2026)

ตรวจทั้งระบบ (core Go + cockpit + tablet) ว่าฟังก์ชันครบพอบินจริงไหม

### ✅ มีครบแล้ว — พร้อมบินจริงด้านคำสั่ง + เซฟตี้
**ชุดคำสั่ง (ทั้ง cockpit และ tablet):** ARM/DISARM · TAKEOFF · LAND · RTL(staggered/แยกชั้น) ·
HOLD · GOTO · Waypoint(GROUPED/SEPARATE + servo A/B) · Swarm formation 5 แบบ ·
WAVE · Movement บังคับสด · SERVO · E-STOP · set_mode

**Failsafe อัตโนมัติใน core (`RunFailsafe` 1Hz — backend/internal/fleet/manager.go):**
- **Link lost > 10s → auto RTL** + ALARM event (LinkLostSec) · delayed > 3s → WARN
- **Battery < 15% ขณะ armed → auto RTL** + ALARM event (BattFailsafePct)
- **Geofence herd ต่อเนื่อง** — โดรนดริฟต์แตะเส้น → ดึงกลับเข้าเขต 2m อัตโนมัติ
- **RC override stuck detection** — FC ไม่รับคำสั่ง → แจ้งพร้อมสาเหตุ

**Command-time envelope (core):** เพดาน 120m · arm ต้องแบต ≥ 25% · goto เช็คระยะห่าง 5m ·
goto/waypoint นอก geofence = ปฏิเสธ

**In-flight monitor (cockpit):** collision watchdog 700ms · event stream (link/battery/
safety/geofence) → banner แดง/เหลือง → **mirror ไป tablet banner** ทั้งคู่เห็นพร้อมกัน

**Preflight gate:** mTLS/token · telemetry สด · GPS 3D+sats · แบต ≥ min · separation ·
geofence(advisory) · home · LIVE command-path test · checklist 8 ข้อ

> สรุป: **ด้านคำสั่งและ failsafe อัตโนมัติ ครบพอบินจริง** — link/แบต/geofence มี
> auto-RTL/herd ใน core และ alarm ถึงทั้งสองจอ

## 14. ทำข้อ 1 + 2 แล้ว (25 ส.ค. 2026 · tablet.html อย่างเดียว)

**เกณฑ์สุขภาพต่อลำ** (`droneHealth()` — ตรงกับ failsafe ใน core/manager.go):
- crit: แบต < 15% ขณะบิน (= จุด failsafe RTL) · link ค้าง > 10s (= LinkLostSec)
- warn: แบต ≤ 25% ขณะบิน (= เกณฑ์ arm ขั้นต่ำ) · link ค้าง > 3s (= LinkWarnSec)

**ข้อ 1 — ไฮไลต์ลำวิกฤตในแถบโดรน**
- แถวลำวิกฤต = ขอบแดงกะพริบ + ป้าย "⚠ แบตวิกฤต/ลิงก์หลุด" ข้างชื่อ + เลขแบตพื้นแดง
- แถวเตือน = ขอบเหลือง + ป้าย "⚠ แบตต่ำ/สัญญาณช้า"
- วิกฤตชนะ selected/stale เสมอ (คนคุมต้องเห็นทันทีว่าลำไหน)

**ข้อ 2 — ชิปสุขภาพฝูงบนแถบบน** (`syncHealth()`)
- ปกติ: "✓ ฝูง N ลำ ปกติ" (เขียว) · เตือน: "⚠ D2 แบตต่ำ" (เหลือง)
- วิกฤต: "⛔ 2 ลำวิกฤต · D3 แบตวิกฤต" (แดงกะพริบ) · แตะดู title = รายลำครบ
- แย่สุดในฝูงชนะเสมอ · แคชด้วย healthSig ไม่ churn

**ยืนยันในบราวเซอร์** (ป้อน D3 แบต12%, D5 age12s, D2 แบต22%):
chip = "⛔ 2 ลำวิกฤต · D3 แบตวิกฤต" · D3=`d crit`+badge · D5=`d stale crit` ·
D2=`d warn` · ฝูงปกติ = "✓ ฝูง 3 ลำ ปกติ" · ไม่มีลำ = "— ฝูง" · `node --check` ผ่าน

> เหลือข้อ 3 (preflight อ่านพารามิเตอร์ FC failsafe ผ่าน ParamGet) — งานใหญ่กว่า ยังไม่ทำ
